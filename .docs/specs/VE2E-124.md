### 2.3 ScriptPage (`apps/web/src/pages/ScriptPage.tsx`) đã có gì

- **Đã có version**: nút **Lưu** gọi `POST /jobs/:id/script`, tạo một `ScriptVersion` mới (v+1), bỏ trạng thái đã duyệt và ghi sự kiện `script_saved`.
- **Vấn đề**: các ô (tiêu đề, hook, body, CTA, caption, lời đọc từng cảnh) chỉ cập nhật state trong trình duyệt (`saveField`). Rời trang mà chưa bấm Lưu thì **mất nội dung**. Bấm **Duyệt phiên bản** hoặc **Viết lại** khi đang có chỗ sửa chưa lưu thì server dùng bản cũ, và **chỗ sửa bị bỏ qua mà không báo**.
- Không được dựng hệ thống draft thứ hai cho ScriptPage. Cách xử lý: xem câu hỏi 1 ở mục 7.

## 3. Data model đề xuất (chỉ thêm 2 bảng, không sửa cột cũ)

```prisma
/// VE2E-124: one in-progress form per user and flow (e.g. the new-job page). Never a job: no workflow, no provider call.
model UserDraft {
  id        String   @id @default(uuid()) @db.Uuid
  userId    String   @db.Uuid
  flowType  String   // "job_new" (whitelist)
  payload   Json     // whitelisted form values, ids only - never a secret
  version   Int      @default(1)   // compare-and-set: an older save never overwrites a newer one
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, flowType])
}

/// VE2E-124: per-user defaults of the creation form (options only, never job content).
model UserCreationPreference {
  userId    String   @id @db.Uuid
  options   Json     // whitelisted option keys, ids only
  version   Int      @default(1)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

- Dùng JSON vì luôn đọc/ghi cả khối và không truy vấn theo từng trường (cùng cách với `AutomationProfileVersion.contentConfig`, `ProviderAccount.modelSnapshot`). Hình dạng JSON được kiểm tra bằng một module thuần dùng chung (`packages/domain/src/creation-form.ts`): chỉ giữ key nằm trong whitelist, kiểm tra kiểu và độ dài, bỏ mọi thứ khác.
- **Draft lưu**: toàn bộ giá trị ở bảng 2.1.
- **Defaults lưu**: `entryMode`, `mode`, `autoSourceType`, `language`, `channelId` (xem câu hỏi 2), `contentAccountId`, `durationTarget`, `sceneCountTarget`, `backgroundSegmentsChoice`, `voiceAccountId`, `voiceId`, `mediaAccountId`, `renderAccountId`, `templateId`, `orshotFormat`, `orshotSize`.
- **Defaults không bao giờ lưu**: `topic`, `promptSpec`, `existingScript`, `autoRawScript`, `autoArticleUrl` (server loại bỏ dù client có gửi).
- Không lưu secret hay API key, chỉ lưu id.

### API (theo quy ước `/me/...` hiện có, tất cả cần đăng nhập; ghi thì cần CSRF)

| Endpoint | Việc |
|---|---|
| `GET /me/drafts/:flowType` | Draft hiện tại của **chính user đang đăng nhập** (hoặc `null`) |
| `PUT /me/drafts/:flowType` | Body `{ payload, baseVersion }`. Tạo hoặc cập nhật bằng compare-and-set theo `version`; lệch thì trả `VERSION_CONFLICT` |
| `DELETE /me/drafts/:flowType` | Xoá draft (gọi sau khi gửi job thành công, hoặc khi bấm "Xoá bản nháp") |
| `GET /me/creation-preferences` | Defaults của user (hoặc `null`) |
| `PUT /me/creation-preferences` | Lưu defaults (đã lọc whitelist) |
| `DELETE /me/creation-preferences` | Đặt lại về mặc định hệ thống |

- `userId` **luôn lấy từ phiên đăng nhập**, không bao giờ từ URL hay body. Không có endpoint nào đọc draft/defaults của người khác, kể cả admin.
- Không endpoint nào gọi AI, TTS, media hay render.

## 4. Hành vi trên `JobNewPage`

1. **Thứ tự khi mở trang**: draft của user → defaults của user → mặc định hệ thống. Ngoại lệ: tham số URL (`?entry=`, `?channelId=`) xem câu hỏi 3.
2. **Chỉ bật autosave sau khi đã khôi phục xong**, để giá trị mặc định lúc đầu không bao giờ ghi đè lên draft.
3. **Autosave**: debounce 1,5 giây sau lần thay đổi cuối. Mỗi lúc chỉ có một request đang chạy; thay đổi mới trong lúc đó được gộp vào lần lưu kế tiếp. Server dùng compare-and-set theo `version`, nên một request cũ về sau **không thể** ghi đè state mới. Hai tab cùng sửa thì tab sau nhận cảnh báo, không ghi đè lặng lẽ.
4. **Trạng thái hiển thị**: "Đang lưu…", "Đã lưu lúc HH:mm", "Không thể lưu bản nháp — thử lại" (kèm nút thử lại). Lưu lỗi không bao giờ xoá hay đổi form. Không có popup.
5. **Nút**: "Lưu bản nháp", "Xoá bản nháp", "Lưu các lựa chọn này làm mặc định" (báo "Đã lưu làm tùy chọn mặc định"), "Đặt lại mặc định".
6. **Gửi job thành công thì xoá draft**:
   - Studio: ngay sau khi `POST /jobs` thành công, vì job đã tồn tại dù bước tạo kịch bản sau đó có lỗi.
   - Auto: sau khi `submitVideoProduction` thành công.
   - Gửi thất bại thì giữ draft.
7. **Giá trị khôi phục không còn hợp lệ** (tài khoản bị xoá hoặc chưa verify, giọng hay template không còn, kênh mất quyền): field đó để **trống**, hiện cảnh báo nêu rõ field nào cần chọn lại, các field khác giữ nguyên. **Không tự chọn tài khoản/giọng/template khác thay thế.** Việc tự chọn phần tử đầu tiên chỉ còn áp dụng khi field chưa từng có giá trị (mặc định hệ thống), không áp dụng khi thay thế một giá trị khôi phục bị hỏng.
8. Defaults chỉ được đọc ở `JobNewPage`; **không đụng tới job đã có**, ScriptPage hay Studio.

### Phát hiện khi làm ScriptPage

Nút **Lưu** và **Tạo / Viết lại** của ScriptPage **chưa bao giờ chạy**: handler viết `onClick={() => void (async () => {...})}` mà thiếu `()` gọi hàm. Bấm Lưu không lưu gì, nên đây là nguyên nhân chính của "mất nội dung khi rời trang". Đã sửa. Thêm vào đó:
- cảnh báo khi rời trang (tải lại, đóng tab, bấm link trong app) lúc còn thay đổi chưa lưu;
- tự lưu thành version mới trước khi **Duyệt phiên bản** hoặc **Viết lại**;
- đổi tài khoản content không còn xoá chỗ đang sửa.
